### Logging (binding)

| Level | When |
|-------|------|
| INFO | Startup, migrations, sweeps, **successful** state transitions |
| WARNING | Idempotent no-ops (e.g. manifest ingest skip, `mark_indexed` when already INDEXED, terminal/idempotent early returns that do not raise) |
| ERROR | Transition failures surfaced to callers (before HTTP mapping) — use when `record_failure` is invoked or equivalent failure path; not for happy-path transitions |
| CRITICAL | `emit_alert()` only — `extra` must include `alert_type` and `source_id` |

**§14.3 dual-write (binding):** Each `emit_alert` call writes:
1. `logger.critical(message, extra={"alert_type": ..., "source_id": ..., ...})`
2. `INSERT` into `error_log` with `error_class = "ALERT"`, populated `message`, `state_at_failure`, `attempt_number`, `timestamp`

**M1 trigger wiring (binding):** Inside `record_failure`, after target state is determined:
- `PERMANENTLY_FAILED` → `alert_type = "permanent_failure"`
- `ESCALATION_FLAGGED` due to `retry_count + 1 >= RETRY_MAX_ATTEMPTS` → `alert_type = "retry_budget_exhausted"`
- `ESCALATION_FLAGGED` due to `not is_retriable` or `http_status in ESCALATION_HTTP_STATUSES` → `alert_type = "escalation_flagged"`

Do **not** emit duplicate alerts for the same `record_failure` call.

**Deferred alert conditions (document in decision log, not implemented):**
- `profile_hash_mismatch` — enrichment-batcher / M3
- `batch_timeout_48h`, `batch_abort` — batch-poller / M5
