## 5. Methodology gaps surfaced

**Orchestrator should have prompted for:**
- Explicit §2 row binding `QUERY_API_HOST_PORT` / `UI_HOST_PORT` to `.env.example` (not only `bishop_shared.constants`) — the T1 contract names `.env.example` for `BISHOP_DATA_ROOT` but host ports were constants-only; compose env gap was predictable.
- "Deferred to T5" items on architectural subtasks need a **closure owner** in the receiving packet's kill criteria (T5 packet did not require `.env.example` port vars).
- Pre-audit §8.2 should trigger commit of plan artifacts *before* auditor handoff, not as auditor finding.

**Executor should have blocked:**
- T5 closing with README quick-start that copies `.env.example` only, when compose `ports:` require env vars absent from that file — either HALT or fix `.env.example` in T5 scope (README was in files-to-touch).
- Plan §8.3 evidence row claiming `stub_started` is pytest-verified when the test only checks sleep loops.

**Contracts schema gaps:**
- No distinction between **Python constant defaults** and **compose-interpolated env vars** — same §2 row implied both without a wire binding for `.env.example`.
- Scout §Interface inventory omitted `BISHOP_SERVICES` and `HealthResponse` (greenfield); planner added them — vestigial gap in pre-plan template for greenfield.
